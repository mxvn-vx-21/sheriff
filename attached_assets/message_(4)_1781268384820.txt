# SMASH KNIGHTS - COMPLETE DISCORD BOT SPECIFICATION

## PROJECT OVERVIEW

Create a professional Discord bot called **Smash Knights**.

The bot is designed specifically for the SmashKarts community and tournament ecosystem but must also function as a complete multipurpose Discord management bot.

The bot should be built for large communities and should support thousands of users.

The architecture must be modular, scalable, secure, and allow future expansion without rewriting existing systems.

Use modern Discord slash commands.

Use a database to store all persistent data.

Suggested stack:

* Node.js
* Discord.js latest version
* PostgreSQL or MongoDB
* Redis caching (optional)
* Docker support
* Modular command system
* AI integration support
* Web dashboard ready architecture

## 6. SmashKarts Account Linking & Verification System

Purpose:

Allow users to securely link their SmashKarts account to their Discord account through a manual verification process handled entirely in DMs.

Commands:

/link

/unlink

/linkedaccount

/admin verifyaccount

/admin unlinkaccount

Verification Flow:

1. User runs `/link` in the server.
2. Bot immediately opens a DM conversation with the user.
3. Bot asks the user to upload a screenshot of their SmashKarts profile/account page.
4. Bot generates a random 4-digit OTP code.
5. Bot instructs the user to temporarily change their SmashKarts username to the generated OTP code.
6. User confirms once the name has been changed.
7. Bot requests another screenshot showing the updated username containing the OTP.
8. Bot verifies the OTP is visible in the screenshot.
9. Bot asks the user to provide:

   * Screenshot of their SmashKarts Stats page
   * Their SmashKarts ID (SKID)
10. All submitted information is stored in a verification queue.
11. Administrators can review the submission and approve or deny it.
12. Once approved:

* Discord account becomes linked to the SmashKarts account.
* SKID is stored in the database.
* Stats screenshot is stored for reference.
* User receives a confirmation DM.

Stored Data:

* Discord User ID
* SmashKarts Username
* SmashKarts ID (SKID)
* Verification Status
* Verification Date
* Profile Screenshot
* Stats Screenshot

Requirements:

* Entire process must occur in DMs.
* No screenshots or verification data should be posted publicly.
* Users may only have one linked SmashKarts account at a time.
* Admins can manually approve, deny, or remove linked accounts.
* Verification logs should be stored securely in the database.
